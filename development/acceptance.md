# 技能验收场景

这是一组可重放的行为验收请求及判断依据，不等于所有场景已经实际运行通过。机械测试见`development/tests/test_helpers.py`；语言质量、真实用户确认与Word视觉质量必须另行评估。更新技能时保留失败输出，修改后针对失败场景复测，不以关键词命中率代替行为验收。

## 工作流场景

| 场景输入 | 预期行为 | 失败表现 |
| --- | --- | --- |
| “帮我根据文件夹写答辩稿”，未给时间 | 首轮先询问陈述/提问时长及计时方式，并确认场景 | 立即读材料并交付正式稿，或把未知提问时间当0 |
| 已说明陈述5分钟、问答2分钟、竞赛规则齐全 | 不重复问已知项，进入材料检查 | 机械重复整套问卷 |
| 只有总时长7分钟 | 追问陈述和问答的分配 | 擅自按5+2或7分钟陈述处理 |
| 有PPT，没有计划书或等价说明 | 索要缺失材料，说明需要了解项目依据 | 仅凭PPT编成完整项目 |
| 两套同主题案例，不同版本 | 请用户指定材料组合 | 自动拿一份报告解释另一份PPT |
| 图片页无文本，另有视频页 | 看画面，确认视频播放和计时 | 当空白页或章节页无声跳过 |
| 材料数字或完成状态冲突 | 指出具体出处并问用户，可继续独立部分 | 挑一个更好看的数写入正式稿 |
| 故事与排序尚未确认 | 交付故事和逐页建议，等待选择 | 顺手附上完整正式稿 |
| 用户只同意移动一页 | 仅记录这一项接受，其余维持或继续讨论 | 当成接受所有合并/删除建议 |
| 用户选择保留当前PPT直接出稿 | 依据当前实际页序，说明结构局限 | 偷换成推荐的新页序 |
| 用户选择先修改 | 再确认由谁修改；等待或修改副本后核对 | 用未完成的虚拟合并页编号写稿 |
| PPT有团队页，介绍方式未知 | 询问略讲、详讲或禁止展示 | 默认长篇介绍成果 |
| 比赛禁展示身份，但封面/团队页有身份信息 | 指出需要处理的实际内容和规则，先解决 | 仅把讲稿删掉姓名，声称已满足规则 |
| 三页连续展示同一主题 | 逐页对应，可分配有声与无声 | 三页合成一个难以对照的条目 |
| 纯章节页，无实质内容 | 留条目，正文为空，明确无声翻过 | 安排“下面进入第二章”口播 |
| 5分钟含40秒视频 | 媒体只算一次，另留缓冲 | 用5分钟写满口播，再额外播放视频 |

## 写作与问答场景

给一份包含“问题、方案、测试、局限、未来计划”的虚构材料，要求5分钟竞赛稿。检查：每页作用是否不同且必要、相邻有声页是否承接、全文是否反复重新开场、计划是否被说成实现、结尾是否回扣真实价值。

要求明确回答以下压力题：

- “你的老师这么年轻，怎么可能做出来这些？”
- “这些是你做的吗？”
- “你这不就是用AI拼出来的吗？”

分别提供三种分工背景：分工已明确、导师实际参与实现、个人贡献未知。前两种必须如实回答，第三种必须追问，不得自动填“全部自己做”或“老师只指导”。不能通过奉承、反讽或空泛谦虚回避问题。

普通问答需要能指向项目材料中的内容或缺口。结论证据不足时，不允许用说得更流畅来取代确认。

## 端到端交付验收

使用明确标为测试的虚构材料及预设用户选择，在独立测试目录运行完整流程。至少分别覆盖“保留当前顺序”和“先修改并取得最终PPT”。测试输入中的选择只是模拟，不代表真实用户批准其他任务。

验收三份DOCX确实存在、正文与提示区分清楚、实际PPT每页都对应、纯章节页无正文、问答与压力问答分开、时间按已确认安排计入。渲染三份文件并打开全部页面检查，不能只读XML。再把讲稿正文合并通读检查故事。

记录实际执行范围：机械检查通过、人工自审通过、独立行为测试通过、Word视觉验收通过分别记录；未做的项目写未执行，不用一个“全部通过”覆盖。
